## 一、项目背景与定位

### 1.1 背景

校园二手交易中，卖家最常遇到的问题是"不知道挂多少钱"：
- 挂高了卖不掉，商品长期闲置
- 挂低了自己亏，感觉被捡漏
- 传统定价工具只给一个数字，没有理由、没有置信度、不能交互调整

当前校园二手交易信息分散在 QQ 群、校园频道、表白墙等多个渠道，商品状态不透明（还在/已售/太久没人买丢了），检索能力参差不齐，定价缺乏数据支撑。

### 1.2 产品定位

**AI定价+风控助手是一款 AI-Native 的二手商品智能定价工具**，用户通过输入商品信息（名称/品类/成色/图片），AI 基于真实成交数据输出价格区间 + 置信度标签 + 自然语言定价理由，并支持对话式微调。

**AI-Native，不是 AI-First**：核心体验完全由 AI 驱动——自然语言输入、AI 生成定价理由、对话式价格调整。没有大模型，这个产品就不存在。

### 1.3 与前两个项目的关系

| 项目 | 类型 | 定位 |
|------|------|------|
| 校园二手交易平台 | 完整产品 | 交易闭环（发布/浏览/下单/管理） |
| 足球 AI 助手 | 完整产品 | 赛事预测 + ML 实验 |
| **AI定价+风控助手** | **模块产品** | **AI-Native 定价能力，可嵌入交易平台** |

本项目作为独立模块开发，不直接接入二手交易平台，但设计上预留了集成能力（一键填入售价、发布同款跳转）。

## 二、用户场景与痛点

### 2.1 目标用户

| 用户类型 | 场景 | 需求 |
|----------|------|------|
| 卖家 | 想卖东西但不知道挂多少钱 | 需要参考价，避免挂高卖不掉或挂低自己亏 |
| 买家 | 看到别人卖的东西想知道是否合理 | 判断值不值得买，砍多少合适 |
| 吃瓜群众 | 好奇自己的旧东西值多少钱 | 随手查一下，无明确交易意图 |
| 犹豫发布者 | 想发布但犹豫价格 | 查完价觉得合适直接跳转发布 |

### 2.2 核心痛点

1. **定价无数据支撑**：凭感觉定价，容易挂高或挂低
2. **只有数字没有理由**：传统工具给一个价格，用户不知道为什么是这个价
3. **无法交互调整**：固定价格不能根据个人情况（急售/配件齐全）调整
4. **AI 不确定性无管理**：大模型输出可能不准，缺乏置信度提示和免责声明

## 三、核心功能流程

### 3.1 功能架构

```
AI定价+风控助手
├── 输入层
│   ├── 商品名称（文本输入）
│   ├── 品类选择（7 类预设）
│   ├── 成色选择（4 档预设）
│   └── 商品图片（可选上传）
├── AI 处理层
│   ├── RAG 检索（Mercari 同类成交记录）
│   ├── 价格计算（中位数 + 成色系数 + 四分位距区间）
│   ├── 置信度分级（高/中/低）
│   └── 大模型生成定价理由
└── 输出层
    ├── 建议价格（大字展示）
    ├── 价格区间（双滑块微调）
    ├── 置信度标签（三色标签）
    ├── AI 定价理由（自然语言解释）
    ├── 低置信度免责声明
    └── 对话式微调（自然语言调整）
```

### 3.2 核心流程

**主流程：AI 智能估价**

1. 用户进入首页，看到输入表单
2. 输入商品名称（必填），选择品类和成色（可选），上传图片（可选）
3. 点击"AI 智能估价"按钮
4. 系统调用后端 API：
   - RAG 检索 Mercari 数据集中同类商品成交记录（最多 20 条）
   - 计算中位数价格 × 成色系数 = 建议价格
   - 计算四分位距区间 = 价格区间
   - 根据匹配数量确定置信度（≥15 高，5-14 中，<5 低）
   - 大模型生成自然语言定价理由
5. 结果页展示：建议价格、价格区间、置信度标签、AI 定价理由、参考商品数量
6. 低置信度时展示免责声明

**分支流程：对话式微调**

1. 用户在结果页输入调整意图（如"我急售，便宜点""配件齐全，能贵点吗"）
2. 点击"发送调整请求"
3. 大模型识别意图，调整价格并生成理由
4. 更新结果页的价格和理由

## 四、AI-Native 设计决策

### 4.1 决策一：独立定价模块，不内嵌发布流程

**选择**：AI定价+风控助手作为独立一级入口存在，不内嵌在商品发布流程中。

**背后考虑**：
1. **降低使用门槛**：覆盖"只是想查一下"的泛场景用户，不需要先进入发布流程
2. **反哺转化**：查完价后引导一键发布，反而提升平台的发布转化率
3. **数据飞轮**：查价越多定价越准，用的人越多，既是工具也是获客入口

**与 AI-First 的区别**：AI-First 产品中 AI 是辅助功能，移除后产品仍可运行；AI-Native 产品中 AI 是核心，移除后产品不存在。

### 4.2 决策二：AI 不确定时输出区间 + 置信度 + 免责声明

**选择**：不输出单一价格，而是输出价格区间 + 置信度标签 + 低置信度免责声明。

**背后考虑**：
1. **对冲技术不确定性**：大模型和 RAG 检索可能不准，用区间表达不确定性
2. **管理用户预期**：高置信度（绿色）= 推荐参考，中置信度（黄色）= 仅供参考，低置信度（灰色）= 估算，区间自动拉宽
3. **风控意识**：低置信度时展示免责声明"价格仅供参考，实际成交价以市场为准"

**置信度分级规则**：
| 置信度 | 匹配数量 | 标签颜色 | 区间策略 |
|--------|----------|----------|----------|
| 高 | ≥15 条 | 绿色 | 正常区间（四分位距） |
| 中 | 5-14 条 | 黄色 | 正常区间 |
| 低 | <5 条 | 灰色 | 区间拉宽（±30%）+ 免责声明 |

### 4.3 决策三：价格区间默认锚定中间值 + 双滑块微调

**选择**：双滑块分别控制最低价和最高价，默认锚定 AI 最佳猜测值（区间中间值），用户可左右拖动微调。

**背后考虑**：
1. **降低决策成本**：AI 给最佳猜测，用户在此基础上调整，不需要从零开始
2. **交互自然**：左右滑块直观表达价格区间，实时显示数值
3. **AI-Native 体验**：不是简单的表单输入，而是 AI 给建议、用户做调整的协作模式

### 4.4 决策四：对话式微调，不是表单式调整

**选择**：用户用自然语言描述调整意图（"我急售""配件齐全"），AI 识别意图并调整价格，而不是提供"降价 10%""涨价 5%"这样的表单选项。

**背后考虑**：
1. **AI-Native 交互**：自然语言是 AI 时代的原生交互方式
2. **表达灵活**：用户可以说"这个手机保养得特别好，壳膜都送"，AI 能理解并给出合理调整
3. **生成理由**：AI 调整价格的同时生成调整理由，让用户明白为什么调这么多

**调整规则（大模型 prompt 中定义）**：
- 急售/便宜/降价：下调 5%-15%
- 配件齐全/成色好/涨价：上调 5%-15%
- 其他情况：微调 0%-5%

## 六、数据来源与处理

### 6.1 数据集

**Mercari Price Suggestion Challenge**（Kaggle 公开竞赛数据集）

| 项目 | 内容 |
|------|------|
| 来源 | Kaggle 竞赛：mercari-price-suggestion-challenge |
| 原始规模 | 约 150 万条二手商品成交记录 |
| 字段 | train_id、name、item_condition_id、category_name、brand_name、price、shipping、item_description |
| 清洗后规模 | 41,260 条（7 个品类，每品类最多 8000 条） |
| 文件大小 | 15.1 MB（JSON 格式） |

### 6.2 数据清洗流程

1. **解压原始数据**：从 `train.tsv.7z` 解压得到 `train.tsv`（322 MB，148 万条）
2. **品类映射**：将 Mercari 的英文品类映射为校园高频中文品类（7 类）
3. **成色映射**：将 `item_condition_id`（1-5）映射为 4 档中文成色
4. **价格换算**：美元 × 7.2 = 人民币
5. **采样限制**：每品类最多 8000 条，避免单品类数据过多
6. **输出格式**：JSON，每条包含 name、category、condition、price_cny、brand、description

### 6.3 品类分布

| 品类 | 数量 | 占比 |
|------|------|------|
| 服饰鞋包 | 8,000 | 19.4% |
| 电子数码 | 8,000 | 19.4% |
| 生活用品 | 8,000 | 19.4% |
| 运动户外 | 8,000 | 19.4% |
| 其他 | 8,000 | 19.4% |
| 教材书籍 | 1,214 | 2.9% |
| 电脑平板 | 46 | 0.1% |
| **合计** | **41,260** | **100%** |

### 6.4 RAG 检索策略

**分词策略**：
- 英文：提取单词和数字（如 `iphone`, `13`, `128gb`）
- 中文：提取 2 字组合（如 `手机`, `几乎`, `全新`）

**匹配评分**：
- 对每条候选商品，计算查询词在商品名称/描述/品牌中的命中比例
- 分数 = 命中词数 / 查询词总数
- 只保留分数 > 0 的商品

**检索流程**：
1. 按品类筛选（品类筛选后不足 5 条则放宽到全部）
2. 计算每条商品的匹配分数
3. 按分数排序
4. 同成色的优先排序
5. 返回 top 20 条

### 6.5 价格计算策略

| 步骤 | 方法 | 说明 |
|------|------|------|
| 基准价 | 中位数 | 比均值更稳健，不受极端值影响 |
| 成色调整 | 中位数 × 成色系数 | 全新 1.0 / 几乎全新 0.92 / 轻微使用 0.8 / 明显使用 0.65 |
| 价格区间 | 四分位距（Q1-Q3） | 数据 ≥4 条时用四分位距，否则用 ±15% |
| 置信度 | 匹配数量 | ≥15 高 / 5-14 中 / <5 低 |

## 七、API 接口设计

### 7.1 POST /api/price — AI 智能估价

**请求体**：
```json
{
  "product_name": "iPhone 13 128G 蓝色",
  "category": "手机数码",
  "condition": "几乎全新",
  "image": "base64或url（可选）"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| product_name | string | 是 | 商品名称 |
| category | string | 否 | 品类（7 类预设） |
| condition | string | 否 | 成色（4 档预设） |
| image | string | 否 | 商品图片（暂未使用） |

**响应**：
```json
{
  "suggested_price": 135,
  "price_min": 80,
  "price_max": 1639,
  "confidence": "high",
  "reasoning": "基于20条同类商品历史成交数据（均价¥XXX），几乎全新成色保值较好，综合得出建议价格¥135。价格区间¥80~¥1639反映市场波动。数据充足，置信度较高。",
  "comparables": [
    {"name": "iPhone 13 128GB", "price": 120, "condition": "几乎全新", "category": "手机数码"}
  ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| suggested_price | number | 建议价格（人民币） |
| price_min | number | 价格区间下限 |
| price_max | number | 价格区间上限 |
| confidence | string | 置信度：high/medium/low |
| reasoning | string | AI 生成的定价理由 |
| comparables | array | 参考商品列表（最多 5 条） |

### 7.2 POST /api/price/adjust — 对话式价格微调

**请求体**：
```json
{
  "product_name": "iPhone 13 128G 蓝色",
  "category": "手机数码",
  "condition": "几乎全新",
  "current_price": 135,
  "message": "我急售，可以便宜点"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| product_name | string | 是 | 商品名称 |
| category | string | 否 | 品类 |
| condition | string | 否 | 成色 |
| current_price | number | 是 | 当前建议价格 |
| message | string | 是 | 用户的调整意图（自然语言） |

**响应**：同 `/api/price` 响应格式

## 九、面试核心讲点

这个项目面试时核心讲**三个产品决策**：

1. **把AI定价+风控助手独立成一级入口而不是内嵌发布页**——展现产品架构思维和转化漏斗意识
2. **AI 不确定的时候输出区间 + 置信度 + 免责声明**——用产品设计对冲技术不确定性，展现风控意识和用户预期管理能力
3. **定价区间默认锚定中间值 + 双滑块微调 + 对话式调整**——展现对用户体验和决策成本的关注，以及 AI-Native 的交互设计思维

**一句话收尾**：这是一个低频工具反哺高频交易、构建数据飞轮的 AI-Native 产品设计。
